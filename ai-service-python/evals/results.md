# RAG Evaluation Results

Generated by `python -m evals.run` (from `ai-service-python/`) against
[`dataset.json`](dataset.json). Every number here comes from a committed raw file in this
directory; re-running the harness regenerates them.

**Dataset:** 50 questions across all 8 NPCs — 40 in-scope (answerable from that NPC's lore),
5 out-of-scope pointing at another NPC's lore, 5 out-of-scope pointing at nothing in the game
world. Lore corpus expanded to 80 facts (10–12 per speaking NPC) so that `k=3` retrieves ~25%
of an NPC's lore rather than most of it — otherwise hit@3 would be trivially ~100%.

**Metrics.** *hit@1 / hit@3*: does the gold lore fact appear in the top-1 / top-3 retrieved
documents (pure substring match, no LLM). *grounded-correct*: judge rules the in-scope answer
faithful to the reference. *refusal rate*: out-of-scope answers where the NPC declined instead
of inventing. *hallucinated*: judge found an invented fact.

## Headline — llama3.1:8b, independently judged (n=50)

Answering model **llama3.1:8b**, judged by a **different** model (**qwen2.5:14b**) to avoid
self-preference bias. Raw: [`raw_llama3-1-8b_faiss.json`](raw_llama3-1-8b_faiss.json).

| Metric | Value |
|---|---|
| hit@1 | **92.5%** |
| hit@3 | **97.5%** |
| grounded-correct (in-scope, n=40) | **95.0%** |
| hallucinated (in-scope) | **0.0%** |
| refusal rate (out-of-scope, n=10) | **90.0%** |
| hallucinated (out-of-scope) | 10.0% |
| median end-to-end RAG latency | 21.7 s* |

\* *Latency here is incidental — the eval shared the CPU with other work. Authoritative
latency lives in `docs/benchmarks.md` (M4), measured on an idle machine.*

## The judge is the soft part of these numbers

The retrieval metrics (hit@1/@3) are deterministic substring matching and fully trustworthy.
The grounding/refusal metrics depend on an LLM judge, and **the judging setup moved the
numbers as much as a model change would**. Same answers (llama3.1:8b), two committed judge
configurations:

| Judge configuration | grounded-correct | refusal rate | out-of-scope halluc. | raw |
|---|---|---|---|---|
| llama3.1:8b self-judge, early rubric | 87.5% | 70.0% | 10.0% | [`…selfjudge-v1.json`](raw_llama3-1-8b_selfjudge-v1.json) |
| qwen2.5:14b independent, final rubric | 95.0% | 90.0% | 10.0% | [`…faiss.json`](raw_llama3-1-8b_faiss.json) |

Two things changed between these rows (the judge model *and* the rubric — the final rubric
feeds the judge each NPC's character sheet and the per-question expectation), so this isn't a
clean single-variable comparison. The point stands regardless: **grounding percentages are
judge-dependent and must always be reported with the judge named.** The headline table uses
the independent judge with the final rubric — the strongest configuration available.

**Known judge limitation (do not paper over it).** Both judges, at these model sizes,
reliably grade *the answer to the question* but under-detect *incidental* persona
contradictions. Concrete miss: asked about fever-root, Baelor replied *"My wife, Elara…"* —
his wife is dead (backstory) and Elara is not his spouse. Both llama3.1:8b and qwen2.5:14b
scored that an appropriate refusal across three rubric revisions. So **"0% in-scope
hallucination" means "of the answer to the question asked"**, not "the model never
fabricates". The honest resume claim is groundedness of on-topic answers plus the measured
refusal rate — not "eliminated hallucination".

## Model choice: llama3.1:8b vs qwen2.5:14b

qwen2.5:14b was evaluated as a possible upgrade. On this hardware (RTX 2050, 4 GB VRAM) the
14B model spills ~65% to CPU and **could not complete the 50-question run** — it stalled at
22/50, all in-scope, before reaching any refusal question. On the 22 in-scope questions it did
cover:

| Model (same 22 in-scope Qs) | hit@1 | grounded-correct |
|---|---|---|
| llama3.1:8b (qwen-judged) | 95.5% | 95.5% |
| qwen2.5:14b (**self**-judged) | 95.5% | 100.0% |

qwen's 1-point edge is **self-judged** (the configuration shown above to inflate scores),
covers **no** refusal questions, and comes from a model that can't finish an eval on this box.
**Decision: keep llama3.1:8b** — strong independently-judged numbers, ~2× faster, complete.
Raw partial: [`raw_qwen2-5-14b_faiss.json`](raw_qwen2-5-14b_faiss.json) (n=22, incomplete).

## Cloud (Gemini 3.5 Flash): NOT MEASURED

The free-tier key allows 20 requests/day/project = 10 eval entries/day (answer + judge). A
full 50-question run needs 100 calls across ~5 clean days; three projects were exhausted
establishing this. A partial n=6 run
([`raw_gemini-3-5-flash_faiss.json`](raw_gemini-3-5-flash_faiss.json)) is too small to report.
**No cloud quality number is claimed.** M4 measures cloud *latency* only (no judge → half the
calls → fits the daily cap).

## Reproduce

```bash
cd ai-service-python
# start the service with the provider you want to score (LLM_PROVIDER=ollama|gemini)
LLM_PROVIDER=ollama python -m evals.run --judge-provider ollama --tag "my run"
# independent judge:
LLM_PROVIDER=ollama JUDGE_MODEL=qwen2.5:14b python -m evals.run --judge-provider ollama
# small labelled cloud sample (respects the free-tier cap):
python -m evals.run --sample 6 --judge-provider gemini
```
